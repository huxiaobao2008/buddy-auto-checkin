一、审查结论摘要

对项目执行了 6 层全栈审查（core 基础设施 → engine 引擎 → missions 任务模块 → orchestrator 编排 → web 工作台 → docs 文档与流程图），并专项定位了工作台「续期所有凭证」后账号信息全部查询失败、找不到任务列表的重大故障。根因链已完整实证：

data/atrest.key 缺失 → creds.read_auth_file() 静默跳过信封解密（core/creds.py:62-68） → capture()[续期] 把 {$wbEncrypted} 信封对象原样覆写进 accounts/*.cred.json（core/creds.py:235） → load_cred() 仅校验 accessToken 非空而放行信封（core/creds.py:93-94） → core/api.py 用 "%s" 拼接出 Bearer {'$wbEncrypted':1,...} 请求头 → Growth API 全部 401 → 「账号信息查询失败 / 任务列表为空」

同时确认 1 个「流程图与实际运行行为不匹配」的执行缺陷（claim.py 收尾旅行检查传 cred=None，永远静默失败）、1 个密钥缓存缺陷（补 key 后常驻进程不生效）及 2 个低危项。修复方案与验证计划见报告第五、六节。

5.1 core 层（config / api / creds / atrest / cdp / logs）

校验维度结论判定
凭证链路正确性P0 根因所在：creds.py:62-68 在 atrest_key() is None 时静默跳过解密；:235 将 {$wbEncrypted} 信封原样覆写进 accounts/*.cred.json；:93-94 load_cred 只校验 accessToken 非空，放行信封 → api.py 请求头变成 Bearer {'$wbEncrypted':1,…} → 全部 401P0 阻断
密钥缓存语义P2：atrest.py:282-283 无论是否取到 key 都置 _key_cache["loaded"]=True；进程内首次失败后，即使补上 key 文件仍返回 None，常驻 web 服务必须重启才生效P2 中
AES-GCM 实现正确性atrest.py 纯标准库 AES-256-GCM 按客户端 app.asar 逐字节核对实现；用旧项目密钥实测解密全部凭证成功（RS256 JWT 有效），算法本身正确通过
HTTP 层 401 闭环api.py 超时 20s、网络异常返回 (-1, error)；401 属「温和失败」被白名单跳过 → 症状表现为「查不到任务列表/积分不变」而非报错，符合用户观察链路确证
静态告警甄别missions_api:244 / cdp:292 / switch:126 等告警经逐行核对为链式 .get()、staticmethod 静态推断误报，or {} 兜底后运行时不崩误报

六、问题清单（按优先级）与修复方案

级别问题根因与证据修复方案（T5 落地）
P0 「续期所有凭证」后账号信息全部查询失败、任务列表为空 atrest.key 缺失 → creds.py:62-68 跳过解密 → :235 信封覆写 → api.py 拼出 Bearer {'$wbEncrypted':…} → 全员 401。
证据：旧项目 key 实测可解密全部凭证（有效 JWT，余 27.6–55.0 天）；备份包无 key；cred.json 时间为续期窗口内		 ① 恢复 data\atrest.key（复制自 buddy-auto-v2，已验证可解密）
② 加固 creds.py：无 key 时 capture 显式失败并拒绝覆写信封
③ load_cred 检测 envelope 未解密 → 返回明确错误
④ 重启常驻 web 服务
P1 收尾「猫猫旅行二次检查」静默失效（流程图 ≠ 实际行为） claim.py:22 传 cred=None → missions_api 内 None.get("auth") 抛 AttributeError → except 吞掉返回 FAIL → 分支恒不满足，注释承诺的功能从未执行 claim_account 中先用 CR.load_cred(account) 获取凭证再传给 dispatch；失败时如实上报而非静默跳过
P2 atrest.load_key 缺失也置缓存位，补 key 不生效 atrest.py:282-283 无条件 loaded=True；常驻进程首次无 key 后，补上文件仍返回 None，必须重启 无 key 时不置缓存（或按文件 mtime 失效重读）；load_key 结果变化时自动重载
P3 build_opensource 引用不存在的 skill/、tests/ 目录 INCLUDE 清单含 skill/、tests/，当前项目无此目录，复制被静默跳过；开源包会缺少本应打包的示例/测试 目录存在性守卫 + 缺失告警；按实际目录刷新 INCLUDE 清单
P3 多处注释/文档与实现轻微漂移 如 claim 注释（2026-09-25）宣称的旅行复检实际失效、个别常量注释过期 修复后同步更新注释与 docs 流程图（旅行复检以真实执行为准）
修复边界：本次修复仅限「凭证解密与落盘契约、旅行复检传参、密钥缓存」三项行为缺陷及文档同步，不改变任何业务事实、任务语义与计分规则；优化遵循项目既有零第三方依赖、纯标准库风格。所有修改将按「服务端真实积分/接口响应」作为验收凭证，不以工具成功代替。
