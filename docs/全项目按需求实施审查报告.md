## 三、确认的缺陷清单（8 项，全部已修复）

### A-1 `hotkey()` 未定义，Esc 键静默失效【P0 真 bug】

- **位置**：`engine/driver.py:316`（`reset_to_clean_home` 内）
- **现象**：回首页时关闭浮层的 Esc 键**从未真正发出**
- **根因**：调用了全项目不存在的 `hotkey()`，NameError 被
  `except Exception: pass` 静默吞掉
- **影响**：`reset_to_clean_home` 是所有 UI 任务的前置步骤，
  Esc 失效导致浮层可能未关闭就点「新建任务」，影响面覆盖全部 15 个 UI 任务
- **修复**：实现 `hotkey(name, modifiers=0, timeout=10)`，
  走 CDP `Input.dispatchKeyEvent`（与项目既有键盘实现一致），
  内置 10 种按键；调用点改为记录失败原因而非静默吞掉
- **验证**：`tests/test_audit_fixes.py` A-1 组 5 项断言

### A-2 4 个文件带 UTF-8 BOM 头【P2 隐患】

- **位置**：`engine/switch.py`、`engine/tasks.py`、`launcher.py`、`missions/panels.py`
- **影响**：Python 容忍 BOM，实际不致故障；但导致 AST 工具解析失败，
  且首行 `# -*- coding: utf-8 -*-` 声明形同虚设，跨编辑器编辑易出乱码
- **修复**：移除 BOM
- **验证**：字节级检查 + 42 文件零警告编译

### A-3 三处 HTTP 响应体未关闭【P1 资源泄漏】

- **位置**：`core/cdp.py:217` `list_pages()`、
  `client_cdp.py:50` `_get()`、`orchestrator/adaptive.py:167` `cdp_ready()`
- **现象**：`urlopen` 返回的响应对象未 `close()`
- **影响**：这三个函数都是**高频调用**（每次 CDP 交互、每次探测），
  长时间运行会累积占用连接，Windows 下更明显，最终导致请求失败
- **修复**：改用 `try/finally` 保证关闭
- **验证**：测试 A-3 组 3 项断言

### A-4 Web 层并发竞态，违反串行铁则【P0 真 bug】

- **位置**：`web/server.py` 的 `action_run_account` / `action_run_all` / `action_run_ui_code`
- **现象**：服务器是 `ThreadingHTTPServer`（多线程处理请求），
  但任务守卫「检查 running」与「置位 running=True」之间**无锁保护**；
  快速双击可同时启动两个任务
- **影响**：两个任务同时操作同一客户端 → **直接违反串行铁则**，
  可能造成页面混乱、找不到入口（这正是铁则要防的情况）
- **附加问题**：`action_run_ui_code` 等待旧任务只等 5 秒就继续，
  旧任务未退出时新任务已启动
- **修复**：
  - 三个入口统一改为「检查 + 置位」在同一把 `LOCK` 内完成
  - 单任务改为带 30 秒超时的等待，超时明确拒绝而非并发启动
- **验证**：测试 A-4 组 3 项断言

### A-5 人工跳过分支为死代码【P2 可追溯性】

- **位置**：`orchestrator/batch.py:61` `UNAUTOMATABLE_CODES = []`
- **现象**：2026-09-25 改为从 config 动态读取后，该常量恒空，
  下方依赖它的跳过分支永不可达
- **影响**：功能实际正常（走 `_skip_codes()`），但阅读者会误判该分支有效，
  且需求六的三类理由无法在该分支被验证
- **修复**：显式标注为死代码，调度处改为
  `if code in _skip_codes() or code in UNAUTOMATABLE_CODES` 双条件，
  保留兼容性同时恢复可追溯性
- **验证**：测试 A-5 组 6 项断言

### A-6 日志文案与实现不一致【P2】

- **位置**：`orchestrator/batch.py:856`
- **现象**：日志写「创建 1 个自动化任务（跑完删掉）」，
  但实际 `do_automation_1_and_clean()` 默认 `keep=True` **不删除**
- **影响**：排障时误判删除时序。真实删除由末尾清理闸在积分到账后执行
  （**实现本身是正确的，删除铁则未被破坏**）
- **修复**：文案改为「暂不删除，待积分到账后由清理闸统一删除」，
  并加注释说明时序
- **验证**：测试 A-6 组 2 项断言 + 删除铁则 3 项断言

### A-7 panels.py 正则转义警告【P3】

- **位置**：`missions/panels.py:287`
- **现象**：JS 字符串非 raw string，`\s` 被 Python 解析产生 SyntaxWarning
- **修复**：改为 `r"""`，并确认该字符串仅含 `%s` 占位符，格式化不受影响
- **验证**：全项目零警告编译

### A-8 重复 docstring【P3】

- **位置**：`web/server.py:action_run_account`（上一轮已修）
