# 开源同类项目对比（buddy-auto-v2 vs 社区方案）

> 调研时间：2026-10-20 · 一手来源：各仓库 README / SKILL.md 原文，非二手转述。
> 用途：明确本项目的差异化定位，作为开源发布时 README「与同类项目的区别」一节的素材。

## 一、样本（公开可查的 4 个同类项目）

| 项目 | 形态 | 核心能力 | 首次发布 |
|---|---|---|---|
| `88lin/workbuddy-auto-signin` | 单文件 Python，MIT | 签到 + 成长中心全套（旅行礼物 / 派 Buddy / 开盲盒 / 领任务奖 / **断登补签** / **连登兑换**） | 2026-08-18，持续维护 |
| `liubinne/workbuddy-free-credits` | 轻量脚本 | 每天 06:05 自动领 100 积分 | — |
| `lk610322lk-creator/workbuddy-cloud-checkin` | GitHub Actions 云端 | 签到搬到云端，**关机也能签** + 微信/钉钉/企微/邮件通知 | v1.0.0，MIT |
| xujun.org 博主方案 | 单账号脚本 | 本机计划任务 + 登录态直调接口 | — |

**共同点：4 个全部是单账号。** 其中两个在文档里明确表态——
- `cloud-checkin` 免责声明：「请勿用于批量注册、多账号薅取或任何商业牟利用途。」
- xujun.org：「多账号轮换薅签到奖励性质上不太合适……双账号要杀进程、换登录态文件、再切回来，**链路一长必翻车**。」

## 二、逐项对比

| 维度 | 社区方案（4 个） | buddy-auto-v2（本项目） |
|---|---|---|
| **账号规模** | 全部单账号 | **20 账号池**，串行切号调度 |
| **运行位置** | 本机；`cloud-checkin` 云端 Actions | 本机（UI 阶段需客户端在线） |
| **成长中心** | 88lin 全套（含补签、连登兑换 7/14/28 档） | 盲盒 / 派 Buddy 旅行 / 出行奖励 / 成长任务接取领取；**无补签、无连登兑换**（缺口） |
| **浏览器自动化** | 无（纯 API） | **CDP 驱动 19 个 UI 任务**（无 API 的任务也做） |
| **Web 工作台** | 无（命令行 + JSON/log） | **有**：实时进度、一键全自动、停止任务、切号、续期、发现新账号 |
| **积分过期台账** | 无 | **有**：可用积分 + 每批过期倒计时 + 优先消耗顺序 + 较上次增减 |
| **断点续传** | 不需要（单号） | **有**：今天已完成的账号自动跳过 |
| **并发/占用冲突** | 不会遇到 | **有**：客户端占用令牌（串行铁则），防止并行操作串号 |
| **付费任务拦截** | 无 | **有**：捐款 / 付费类任务一票否决，只记不刷 |
| **登录态失效判定** | 单次 401 即判定 | **有**：401 抖动重试确认后才判死（2026-10-18 凌晨事故经验） |
| **平台** | Win / macOS / Linux（88lin）、Win 实测（cloud） | **仅 Windows**（依赖客户端 CDP + 任务计划程序） |
| **代码规模** | 单文件 / 脚本集合 | **16,867 行 Python**（core+engine+missions+orchestrator+web） |
| **开源脱敏** | 无敏感数据需处理 | **有**：`tools/build_opensource.py` 手机号/JWT 脱敏 + 出包校验 |

## 三、我们的代差级优势（别人做不到）

1. **规模化**：4 个样本全是单账号，且有作者公开判断"多账号必翻车"。本项目把 20 账号的切号、续期、断点续传、占用冲突做成了稳定链路——这是架构代差，不是功能多少的问题。
2. **UI 驱动补齐 API 盲区**：别人只能调接口；对没有开放接口的任务，我们用 CDP 真实操作客户端完成。
3. **决策维度**：别人告诉你"领了多少"，我们还告诉你"还剩多少、哪批哪天过期、先用哪个号、这轮净增多少"。
4. **工程化防御**：付费拦截、401 抖动不误判、串行铁则、日志协议归一化——这些是长期跑出来的，不是设计出来的。

## 四、我们确实不如别人的地方（诚实记录）

1. **不能云端跑**：`cloud-checkin` 关机也能签到；我们依赖本机开机 + 客户端在线。这是真实差距。
2. **仅 Windows**：88lin 支持 Win/macOS/Linux。
3. **缺断登补签与连登兑换**：88lin 有（`/redeem` tier=7/14/28，有双形态兜底），我们没有。属于可补的功能缺口。
4. **部署门槛高**：1.7 万行多模块 vs 单文件 clone 即用，劝退轻量用户。
5. **必须切号**：UI 阶段要真实切换客户端账号，存在占用窗口；单账号方案无此问题。

## 五、开源发布注意事项（风险提示）

- 多账号能力是本项目最显眼的差异点，但**也是社区最敏感的争议点**（两个同类项目明文反对多账号薅取）。公开发布时建议：定位为「多账号统一管理工具」而非「批量薅积分工具」，强调用于管理自己名下账号。
- 脱敏包已排除 `accounts/`、`logs/`、`data/`、`config.json`，并对手机号与 JWT 做替换 + 出包校验；发布前仍建议再跑一次 `python tools/build_opensource.py` 确认校验通过。
- 所有同类项目都声明"非官方、接口来自 app.asar 逆向、可能随时变动"，本项目 README 宜保持同样口径。
